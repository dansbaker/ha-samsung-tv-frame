# Local Art API probe

Target: 2024 Frame LS03D, normal watching mode, authenticated local Art channel. A read-only `get_content_list` request without category returned an event named `get_content_list`, correlated by `request_id`, with a JSON-encoded `content_list` string containing 112 records. Records contained category, content type, dimensions, image date, matte, slideshow and content ID fields. No timeout was observed. A JPEG upload without selection returned a newly assigned content ID, which appeared in a subsequent list. Deleting that ID returned success, and a subsequent list confirmed removal. No pre-existing content was changed. Probe did not test offline or timeout conditions.

# Tokenless Art reconnect, watching mode

On the authorized 2024 LS03D, a secure Art websocket with the previously approved integration client name and no token returned `get_content_list` with 112 records. The user confirmed no TV authorization prompt. A separate previously approved probe client also listed 112 records tokenless without a prompt. A token-bearing Art reconnect during HA restart produced a user-observed Home Assistant authorization prompt despite First Time Only. This proves a viable tokenless read on this model, not compatibility across other models or firmware. Remote-control pairing remains separate. No content was changed in these probes.

# Local external-source control, 2024 LS03D

In watching mode, one tokenless `com.samsung.tv.mobilebff` WebSocket connection using the previously approved Home Assistant client name returned `ms.channel.connect`. The user observed no approval prompts on the preceding two connections. `get.extsources` with empty parameters returned a list of source objects and current flags, with matching string `seqId`. `launch.extsource` with `requestId` set to a listed source ID returned statusCode `"100"` (a string) and response status `ok`, correlated by `seqId`. Switching from a listed HDMI source to TV and back produced the expected current-source flags after four seconds, and the user confirmed the original Fire TV picture was visible. Original input was restored. Timeout and authorization rejection were not deliberately induced on the TV; automated tests cover failure handling. Input identifiers and response values in tests are synthetic. This is evidence for this TV and watching mode, not other models, sleep states, or firmware.

The staged-upload and cleanup-retry implementation is provisional. Automated tests use synthetic IDs and mocked responses. It has not been verified on the target TV in Art Mode, including interrupted selection, current-art readback and cleanup retry. The existing upload/list/delete probe above covered watching mode, not these recovery scenarios. Do not treat the recovery code as release-ready until a reversible, authorized Art Mode test confirms each operation and the original displayed artwork is restored.

# Art Mode selection and restoration through Home Assistant

On the authorized 2024 LS03D in Art Mode, the existing integration's `select_art` service with `show: true` selected a different existing user-uploaded picture. Home Assistant's current-art sensor changed to the selected content ID. Selecting the original preinstalled picture with the same parameters restored the sensor to its original content ID. The TV was returned to its previous watching mode, and the daily automation was re-enabled. The integration implements this service using `select_image` with `category_id: null`, `content_id`, and `show: true`, followed by coordinator refresh and `get_current_artwork`. This was an integration-level observation: raw response correlation and timeout behavior were not separately captured, and interrupted uploads and deletion retries were not tested. Selection/readback was observed, not a physical-screen inspection.
